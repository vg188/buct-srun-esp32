# 凭据与隐私

## 本地配置

复制 `BUCT_AutoAuth/Config.local.example.h` 为同目录的 `Config.local.h`，填写真实凭据。`Config.h` 会优先加载该文件。不要将真实值写入示例文件。

`Config.local.h` 已被 Git 忽略，但 `.gitignore` 不会阻止 `git add -f`，也不会让曾经跟踪的秘密从历史中消失。提交前检查暂存区，而不是只看工作区。

## 不应公开的内容

- WiFi SSID/密码、校园网账号/密码、GitHub 等访问令牌。
- 固件二进制及构建中间文件：它们可能包含编译进去的凭据。
- 原始串口日志、抓包、门户响应：可能包含账号、IP、MAC、认证参数。
- 本机个人路径、设备序列号和未经脱敏的截图。

固件不再打印 HTTP 查询串或原始登录响应。状态快照仍显示本地 IP/网关/DNS，发布日志前应删除或替换为示例值。

## 发布检查

在暂存需要发布的文件之后执行：

```powershell
python tools/check_release_privacy.py
```

工具只读暂存区，拒绝已填入真实值的公共配置、常见令牌/私钥、个人路径和不应发布的文件类型。它是规则检查，不能发现所有类型的秘密，仍需人工审阅 `git diff --cached`。不要依赖它代替凭据管理。

项目仅发布源码和使用合成数据的测试，不提供包含个人凭据的预编译固件。若凭据误提交，应先轮换凭据，再处理仓库历史；仅删除当前文件不足以消除泄露。
