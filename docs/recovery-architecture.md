# 恢复架构与维护边界

本版本以 `beaaa44` 为基线，将恢复调度与已跑通的认证协议分离。默认优先保留现有会话，不根据公网探测失败擅自登出。

## 模块职责

| 文件 | 职责 |
| --- | --- |
| `BUCT_AutoAuth.ino` | Arduino/ESP-IDF、原生 USB、LED、状态计数与快照 |
| `auth_controller.h/.cpp` | 状态机、关联/DHCP 窗口、退避、核对周期与换号冷却 |
| `srun_auth.h/.cpp` | 原有 HTTP/JSONP、challenge、登录和门户状态查询 |
| `srun_crypto.h/.cpp` | 原有加密计算，未改动 |
| `Config.h` / `Config.local.h` | 公共行为参数 / 本地私密凭据 |

控制器通过 `Port` 接口调用外部能力，所有状态由主循环维护。测试注入内存中的链路、时钟与 HTTP 响应，不操作硬件或实际门户。

## 状态机

```text
WIFI_CONNECTING
  未关联 AP：30s 超时 → disconnect → 等 250ms → begin
  已关联 AP：另给 DHCP/IP 90s 窗口
  IP/网关就绪 → ROUTER_SETTLING（10s）→ CHECKING
    探测成功 → ONLINE（30s 后复查）
    门户在线 → 等 10s，不登出
    门户离线或未知 → 原登录路径
      OK / ALREADY_ONLINE → VERIFY_LOGIN（1.5s）→ 探测
      普通错误 → 5/10/30/60s 退避
      E2901 → FATAL_CREDENTIALS，直到重启
  非致命状态发生链路丢失 → WIFI_CONNECTING
```

- `esp_wifi_sta_get_ap_info` 判断关联，不将 `WL_CONNECTED` 当作唯一的 DHCP 阶段依据。
- 控制器独占重试调度，关闭 SDK 自动重连；250ms 是应用层缓冲，并非所有 SDK 时序都已验证。
- 使用无符号时间差处理回绕，等待从同步操作结束计算，不用绝对零时间戳表示“立即执行”。
- 会话核对周期独立于 ONLINE 状态变化，避免失败换号触发密集复查。
- 串口后连接会打印快照，不补发历史日志；独立供电不等待串口。

## 会话安全

`ACCOUNT_REPLACEMENT_ENABLED=0` 时控制器不会调用登出。门户在线但探测失败仍沿用发布基线的等待策略。账号不一致只告警，不比较账号后缀或随意归一化账号。

显式允许换号后，开始尝试即计入冷却，失败也计入；冷却跨 WiFi 重连保留，不跨整机重启持久化。操作可影响 NAT 下全部设备，仅应在维护窗口启用。

`getOnlineInfo()` 的未知响应返回 false；明确的 `not_online_error` 返回已知离线。`logout()` 查询失败返回 false，不能当作已成功登出。查询未知时仍可尝试登录，保留基线兼容性，因为查询与登录接口可能分别失效。

## 性能与已知限制

- 正常在线每分钟约两次成功探测，每半小时核对门户。前一个探测成功后不会继续请求剩余站点。
- 保留 `WiFi.setSleep(true)`，未启用深度睡眠或动态 CPU 降频；不能仅凭日志推断温度或功耗。
- HTTP/DNS 仍为同步实现。网络异常时可能延迟 LED、状态心跳和断线响应，不能把单次连接超时解释为整轮检查严格上限。
- 协议仍使用动态字符串；尚未完成新版长期内存/温升测量。
- 真正的残留会话可能需要人工处理；不以频繁登出换取推测性的恢复。

## 验证记录

2026-10-01 用户提供的诊断版实机日志显示：取得 IP、三个探测站 204、门户核对、周期检查及监视器重新连接均正常。期间登录和登出次数均为零，因此不能据此声称完整登录已经通过测试。

离线测试包含 25 个控制器、13 个协议、12 个集成场景。集成测试中的 120 天是加速模拟时钟，不是设备已连续运行 120 天。诊断日志测试验证独立供电、串口连接/重连、周期快照不额外发起网络请求。

发布前基线检查验证加密文件字节内容不变，HTTP/登录实现仅允许列明的状态返回语义和日志脱敏修改。Arduino-ESP32 3.3.12 目标源文件编译检查不等同于完整固件链接或重新上传。

## 后续维护窗口验收

1. 先在备用/隔离 AP 上测试晚启动、DHCP 延迟和 WiFi 丢失，尽量不影响主网络。
2. 用户允许中断后，再测主路由器重启、WAN 暂断、ESP32 先上电三分钟等情形。
3. 在允许重新认证的窗口验证完整登录；保留计时与状态，分享前脱敏。
4. 持续观察数小时至更长时间的重连次数、内存与温度，再评估是否需要网络层总时限等后续改动。

不要在日常用网时进行登出或断电测试。变更源码不会自动更新设备中的固件。
